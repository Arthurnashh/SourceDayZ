# SQF / SQS — устаревший скрипт движка

> Локальный источник истины: `ComRef/comref.xml` (519 KB, руководство команд, сгенерированное
> самим движком), интерпретатор `El/Evaluator/` и слой корутин `lib/scripts.cpp`.
> Всё здесь прочитано в исходнике в `D:\SOURCEDAYZS!!\DayZ-0.45.124252`.

## 1. Что такое SQF

SQF (*Status Quo Function*) — оригинальный скриптовый язык движка Real Virtuality,
старше Enforce. Он всё ещё жив в 0.45, потому что миссии, `init.sqf`, `execVM`
и большая часть старого геймплея зависят от него. SQS — более ранний вариант, в котором
каждая строка файла является командой (без блоков); движок поддерживает оба.

SQF — язык **одного выражения**: в нём нет объявлений функций, как в C.
Всё является значением, а программа — дерево вызовов. Файл `.sqf` вычисляется
как выражение; результат последнего выражения — возвращаемое значение скрипта.

Доказательство того, что движок трактует скрипт как асинхронно загружаемый объект:
`lib/scripts.hpp:75` — `class Script : public RequestableObject, public IDebugScript`.
Каждый файл `.sqf` — объект streaming, а не текст, прочитанный целиком.

## 3. Синтаксические формы

| Форма | Пример | Семантика |
|---|---|---|
| Инфиксный оператор | `a + b`, `a == b` | разрешается по типу операндов |
| Префиксная команда | `getPos player` | команда + аргумент справа |
| Команда с массивом | `setPos [x,y,z]` | единственный аргумент — массив |
| Вызов функции | `call fnc`, `[a,b] call fnc` | код как значение |
| Блок кода | `{ ... }` | значение `CODE`, не исполняется |
| Массив | `[1,2,3]` | индекс с **0** |
| Строка | `"texto"` | внутренние кавычки удваиваются `""` |
| Локальная переменная | `_x` | область функции/скрипта |
| Глобальная переменная | `nome` | namespace миссии |
| Присваивание | `_x = 5` | значение — результат выражения |
| Условие | `if (cond) then {..} else {..}` | `then` обязателен |
| Цикл while | `while {cond} do {..}` | условие — блок |
| Цикл for | `for "_i" from 0 to 10 step 2 do {..}` | числовой цикл |
| Switch | `switch (x) do { case 1: {..}; default {..} }` | равенство |
| Ожидание условия | `waitUntil {cond}` | приостанавливается до истины |
| Приостановка | `sleep 1` | приостанавливает на N секунд |
| Поток | `spawn {..}`, `execVM "f.sqf"` | создаёт кооперативный поток |
| Область | `private ["_a","_b"]`, `params [...]` | объявление области |
| Комментарий | `// строка` и `/* блок */` | |
| Препроцессор | `#include`, `#define`, `#ifdef` | через `PreprocC` |

### 3.1 Вызов команды

Команда — первый токен; аргумент идёт справа. Когда команда ожидает несколько
значений, они упаковываются в массив:

```sqf
_pos  = getPos player;              // команда + аргумент
_dir  = getDir player;              // то же
player setPos [x, y, z];            // три значения в массиве
_unit setDamage 0.5;                // один скаляр
```

### 3.2 Блок кода — это значение

`{ ... }` **не исполняет** ничего: создаёт значение типа `CODE`. Чтобы исполнить, используйте `call`,
`spawn`, `execVM` или передайте блок команде, принимающей код (`waitUntil`, `then`).

```sqf
_meuBloco = { hint "rodou"; };
call _meuBloco;                     // исполняет сейчас, в том же потоке
_meuBloco spawn {};                 // планирует в новом потоке
```

### 3.3 Область видимости

- `_x` — локальная. Без `private` локальная переменная «утекает» в вызывающий скрипт.
- `private ["_a", "_b"]` объявляет локальные в текущей области.
- `params ["_a", ["_b", 0]]` объявляет и проверяет типы/значения по умолчанию.
- Имя без `_` — глобальная миссии (`missionNamespace`).

```sqf
private _soma = 0;
{
    private _v = _x;                // _x — текущий элемент forEach
    _soma = _soma + _v;
} forEach [1, 2, 3];
```

### 3.4 Управляющие структуры

```sqf
if (alive player) then {
    hint "vivo";
} else {
    hint "morto";
};

while { _i < 10 } do {
    _i = _i + 1;
    sleep 0.1;                      // возвращает управление движку
};

for "_i" from 0 to 10 step 2 do {
    diag_log str _i;
};

switch (_tipo) do {
    case "civil": { hint "civil"; };
    case "militar": { hint "militar"; };
    default { hint "outro"; };
};
```

### 3.5 Массивы

Индекс с 0, динамический размер, разнородные:

```sqf
_arr = [1, "dois", [3, 4]];
_first = _arr select 0;             // 1
_arr set [3, "novo"];               // растёт автоматически
_n = count _arr;
{ diag_log str _x } forEach _arr;
```

### 3.6 Строки и числа

```sqf
_texto = "linha com ""aspas"" internas";   // удвоенные кавычки
_num   = 42;                                // int
_real  = 1.5;                               // float
_bool  = true;                              // boolean
```

## 4. Как движок исполняет SQF

Решающий момент: SQF **не интерпретируется строка за строкой наивным парсером**.
Он компилируется в байткод и исполняется кооперативной VM с бюджетом на кадр.

- `lib/scripts.cpp:53-74` — конструктор `Script`: `_baseTime = Glob.time`,
  `_maxLinesAtOnce = 100`. **`_maxLinesAtOnce` — бюджет строк на кадр**:
  поток SQF исполняет максимум 100 строк и возвращает управление.
- `lib/scripts.cpp:76-93` — `ReadLine()` читает файл символ за символом, пропускает начальные
  пробелы и обрабатывает `\r\n`.
- `El/Evaluator/expressCompiler.cpp` (95 KB) компилирует дерево.
- `El/Evaluator/expressInterpreter.cpp` (21 KB) интерпретирует.
- `El/Evaluator/scriptVM.cpp` связывает с движком.

Практическое следствие: плотный цикл **без `sleep`** не замораживает игру — он потребляет
100 команд кадра и возвращается в следующем кадре. Симптом — **падение FPS**, а не
зависание. Это записано в `1.md` §1.2.3.

## 5. Конкурентность: `spawn`, `execVM`, `call`

| Форма | Где работает | Когда возвращается | Использование |
|---|---|---|---|
| `call bloco` | текущий поток | сразу, со значением | чистая функция |
| `_h = bloco spawn` | новый поток | возвращает handle `Script` | длинная задача |
| `_h = execVM "f.sqf"` | новый поток, читает файл | возвращает handle | внешний скрипт |
| `waitUntil {cond}` | текущий поток | когда условие становится истинным | кооперативный polling |
| `sleep n` | текущий поток | через n секунд | пауза |

Бюджет 100 строк/кадр в `lib/scripts.cpp:53-74` — то, что делает `spawn` дешёвым:
нет потока ОС, только запись в очереди скриптов движка.

## 6. Препроцессор

SQF принимает директивы препроцессора через `PreprocC`:

```sqf
#include "\minha_pasta\config.hpp"
#define MINHA_MACRO 10
#ifdef MINHA_MACRO
    diag_log "definida";
#endif
```

Это массово используется DayZ для внедрения `CfgVehicles`, `CfgWeapons` и функций,
общих для клиента и сервера.

## 7. Классические ошибки (и как движок реагирует)

| Ошибка | Что происходит | Доказательство/поведение |
|---|---|---|
| `while {true} do {}` без `sleep` | FPS падает, игра продолжается | бюджет 100 строк/кадр |
| `2^10` в ожидании степени | это не SQF; в Enforce `^` — XOR | см. страницу Enforce |
| `_arr select 10` вне массива | возвращает `nil` и логирует ошибку | без исключения |
| локальная переменная без `private` | может перезаписать локальную вызывающего | динамическая область |
| отсутствует `then` в `if` | ошибка компиляции скрипта | `if (...) then {...}` |
| `sleep` внутри `call` | приостанавливает весь вызывающий поток | используйте `spawn` |

## 8. Связь с Enforce

В движке 0.45 обе VM. SQF — наследие (миссии, `init.sqf`), Enforce — современный
(`Enfusion/src/script/`). Они делят `TimeManager` и один и тот же бюджет
кадра: **медленный скрипт в любой из них отнимает время у отрисовки** (см.
`World::Simulate` в `lib/world.cpp:11795`, вызов `SimulateScripts` в `12213`).
