# Структура исходного кода

> **Это не реверс-инжиниринг.** Это реальное дерево исходного кода Bohemia
> Interactive, поставленное как проект Visual Studio:
> `D:\SOURCEDAYZS!!\SOURCE DEFINITIVA\DayZ-0.45.124252`.
> Все числа ниже измерены `tools/build_source_data.py` (файл за
> файлом, без оценок), и каждое структурное утверждение указывает файл, который его подтверждает.

## 1. Корень проекта

| Элемент | Что это |
|---|---|
| `DayZ.sln` | решение Visual Studio 2010, **6 проектов** |
| `DayZ2010.sln` | парное решение, те же 6 проектов |
| `buildNo.h` | номер сборки, скомпилированный в бинарник |
| `rv.natvis` | визуализатор типов отладчика (`Ref<>`, `RString`, `Vector3`) |
| `DayZ.smproj` | вспомогательный проект сборки, 36 MB, сгенерирован |

Подтверждение решения: `DayZ.sln:1-2` — `Format Version 12.00` / `# Visual Studio 2010`.
Шесть проектов (`DayZ.sln:3-14`):

```text

lib            -> lib\lib2010.vcxproj        (игра)

```

`config.cpp` во время выполнения.

## 5. `Addons/` — упакованный контент

`Addons/` содержит ровно **116 `.pbo` и 116 `.bisign`** (подпись на файл), 6 145 MB.
Это доказательство того, что контент игры не лежит в отдельных папках в этом дереве: он уже
упакован в формат, описанный на вкладке **PBO**.

## 6. Как читать дерево

1. `lib/*.cpp` — поведение (мир, сцена, объект, зомби, сеть, ИИ).
2. `El/` + `Es/` — фундамент (streams, контейнеры, ParamFile, потоки).
3. `Enfusion/` — новый движок, неполный в этом снимке.
4. `extern/` — зависимости и предел модернизации (Bullet 2.76, DXSDK 2010).
5. `cfg/` + `Addons/` — данные: скомпилированный конфиг и подписанные PBO.

Где код уже изменён, вкладка **Изменения** указывает `файл:строка` каждого патча.

> `[ожидает]` сопоставить содержимое каждого PBO файл за файлом (индекс функций
> покрывает только код C++, но не упакованные данные).
