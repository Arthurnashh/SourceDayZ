# Новые реализации

Одиннадцать направлений, которых не было в исходном проекте и которые теперь есть — код, инструменты,
сборки и документация.

## 1. Движок 0.45, компилирующийся на v141

Исходник 2001 года и объявляет `v100`. На этой машине сборка идёт с **MSVC 14.16 (v141)** и
**MSBuild 15.9.30**, создавая `build\inventory-menu-v10\cpp-out-v31\DayZInt.exe`. Потребовались
правки старых заголовков (`math3dp.hpp`, `enf_mathlib.h`, `typeopts.hpp`, `appName.h`,
`wpch.hpp`, `SimulWeatherDX9.hpp` и нескольких `.cpp`), все сохранены в
`backup-v141-compat-20261116/`.

Известные и принятые предупреждения: `C4005` (`DXGI_ERROR_*` между DXSDK 2010 и SDK 10), `C4477` в
`txtd3d9.cpp:3843` и `LNK4217` (`_floor` в `xapobased.lib`). DirectX остаётся **DX9**; миграции
на DX11 не было.

## 4. Перенос анимаций DayZ 1.30

Крупнейшее направление проекта. Полные детали — на вкладке **Анимации 1.30**; кратко:

| Пункт | Значение |
|---|---|
| RTM в `anims.pbo` 0.45 | 2 028 |
| В формате 1.30 (`RTM_0101`) в E6 | **1 390 (68,5%)** |
| Оставлены в `BMTR` 0.45 | 638 |
| Доступная коллекция 1.30 | 7 415 RTM |
| Файлов заменено в манифесте | 1 526 уникальных путей (1 527 записей) |
| Меню 1.30 исключено | 140 файлов |
| Активный геймплей из манифеста | 1 386 |
| Дополнения вне манифеста | 4 (`InjL...breath` ×3, `Ainv...pills`) |
| Заменено треков `ik/` | 84 (включая 2 от батареи) |
| Состояний `batteryLicking` | 4 |
| Trim костей | 1 526 файлов · 1 425,9 → 1 091,5 MB · **−23,45%** (1 523 в первом проходе) |
| Сборка в игре | **E6** (875,8 MiB) |
| Готовая сборка | **E7** (875,7 MiB, 2 IK возвращены) |

**Форматы:** 0.45 использует `BMTR` (v3), с таблицей имён, завершённой нулём, и сжатыми данными
по кадрам; 1.30 использует `RTM_0101`, с фиксированными 32 байтами на имя и 80 байтами на кость на кадр
(20 значений). Движок 0.45 читает оба. Кости сопоставляются по **имени**; порядок отличается
в 100% замен, и это ничего не ломает.

**Покрытие того, что осталось 0.45:** 273 анимации зомби (другой риг), 140 меню, 33
тест/visema/props и ~192 файла игрока, которых нет в 1.30 (смена оружия по слоту, остановки,
мочеиспускание, дефекация, `m4_check`, варианты `_right`, `ik`).

**Решения:** меню 1.30 вне (141 файл, 333 MB сырых / 255 MB после trim); превью инвентаря
возвращено к 0.45 в E6; переходы 1.30 (171 по позе, 512 reload, 80
unjam, 77 weapon switch, 96 attack и 270 hit) не имеют эквивалентного состояния в конфиге 0.45
и были сохранены; смена оружия, остановки и мочеиспускание/дефекация процедурные в конфиге, а не
файлы.

**Проверка:** E6 вошла в мир с `PLAYING` и ванильным базовым уровнем **12**
`not found or empty`, **23** `Bad move` и **15** `Invalid move ... disarm`, без новых ошибок
анимации. Открытый баг — фонарь + батарея (см. вкладку багов).

## 6. Диагностика, встроенная в движок

Временная инструментация, сделавшая баги видимыми:

- `DIAGMOVE` / `DIAGANIM` в `soldierOld.cpp` и `simul.cpp` — одна строка в секунду с
  `pos`, `spd`, `prim`, `info`, `minmax`, `pf`, `ctrl`, `stat` (удалена в V37)
- `[ZombieCollisionDiag]` и `[ZombieCollisionStartOverlap]` в `zombie.cpp`, ограниченные
  1 логом/с на сервере
- чтение RTM на Python (header, кости, кадры), использованное, чтобы доказать корректность
  root motion
- сравнение PBO через BankRev (`-d`, `-properties`) и `CfgConvert -test` для проверки
  конфигов перед упаковкой

## 7. Автоматизированный тестовый лаунчер

Запланированная задача `DayZTestLaunch`: поднимает сервер, ждёт 40 с и открывает клиент на
`-connect=127.0.0.1 -port=2322`. Вместе с чек-листом RPT (12 / 23 / 15 / `PLAYING`)
позволяет сравнивать сборки за минуты. Скрипт также поднимает приоритет игры до
`AboveNormal`, когда параллельно идёт сборка движка.

## 9. Дисциплина версий, WRP и хешей

- `backup-<тема>-<дата-время>/` хранит только затронутые файлы перед каждым изменением
- `build/inventory-menu-v10/restore-point-vNN-*/` хранит исходник + EXE + MAP (+ PDB) перед
  каждой сборкой
- каждый `package-vNN` — изолированная играбельная установка со своими лаунчером и профилем
- `HISTORICO-CORRECOES-E-PENDENCIAS.md` фиксирует SHA-256 EXE, `ui.pbo` и
  `worlds_chernarusplus.pbo` по версиям
- **правило WRP:** клиент и сервер должны использовать один и тот же `worlds_chernarusplus.pbo`
  (ревизия + SHA-256). Если будущая сборка перепакует клиентский WRP, краш при входе
  вернётся. Ручная процедура — в пять шагов в истории.
- **правило PBO:** в префиксе только один слеш (`prefix=bin\`, не `prefix=bin\\`).

## 11. Доска задач, журнал багов и лента GitHub

Страницы **Незавершённое** и **Баги** перестали быть только для чтения. Доска задач и
журнал багов теперь позволяют создавать, редактировать, начинать, блокировать, завершать, переоткрывать и удалять
элементы. Каждое завершение требует результата с четырьмя обязательными ответами: **что было**, **как
исправлено**, **что использовалось** и **сколько попыток** потребовалось, чтобы действительно решить
вопрос. То же для завершённых задач, с текстом, адаптированным под «что было сделано».

Хранение локальное (`localStorage`, ключ `sourcedayz.board.v1`), с экспортом и
импортом `board.json`. У кого есть исходник, может опубликовать доску в
`site-data/board.json` в репозитории **Personed/Game** и курируемый changelog в
`site-data/updates.json`. Публикация использует fine-grained токен с **Contents: Read and write**,
хранящийся только в сессии браузера; без токена путь — экспортировать JSON и закоммитить вручную.

Страница **Обновления** получила две вкладки: **Лента GitHub**, которая читает коммиты, релизы и
манифест `site-data/updates.json` напрямую из `Personed/Game`, и **Ручные обновления**, где
команда записывает курируемый changelog. Страница **Патчи** показывает ту же ленту коммитов в конце,
чтобы опубликованный в репозитории патч появлялся на сайте без ручного редактирования. Когда манифеста
ещё нет, лента объясняет, чего не хватает, вместо падения.
