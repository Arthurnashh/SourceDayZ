# SQF / SQS — the engine's legacy script

> Local source of truth: `ComRef/comref.xml` (519 KB, the command manual generated by the
> engine itself), the interpreter `El/Evaluator/` and the coroutine layer `lib/scripts.cpp`.
> Everything here was read in the source at `D:\SOURCEDAYZS!!\DayZ-0.45.124252`.

## 1. What SQF is

SQF (*Status Quo Function*) is the Real Virtuality engine's original scripting language,
older than Enforce. It is still alive in 0.45 because missions, `init.sqf`, `execVM`
and much of the old gameplay depend on it. SQS is the earlier variant, where each line of the file
is a command (no blocks); the engine keeps both.

SQF is a **single-expression** language: there are no function declarations as in C.
Everything is a value, and the program is a call tree. A `.sqf` file is evaluated
as an expression; the result of the last expression is the script's return value.

Evidence that the engine treats a script as an asynchronously loadable object:
`lib/scripts.hpp:75` — `class Script : public RequestableObject, public IDebugScript`.
Each `.sqf` file is a streaming object, not text read all at once.

## 3. Syntactic forms

| Form | Example | Semantics |
|---|---|---|
| Infix operator | `a + b`, `a == b` | resolves by operand type |
| Prefix command | `getPos player` | command + argument on the right |
| Command with array | `setPos [x,y,z]` | single argument is an array |
| Function call | `call fnc`, `[a,b] call fnc` | code as a value |
| Code block | `{ ... }` | `CODE` value, not executed |
| Array | `[1,2,3]` | **0**-based index |
| String | `"text"` | inner quotes doubled `""` |
| Local variable | `_x` | function/script scope |
| Global variable | `name` | mission namespace |
| Assignment | `_x = 5` | the value is the expression's result |
| Conditional | `if (cond) then {..} else {..}` | `then` is mandatory |
| While loop | `while {cond} do {..}` | the condition is a block |
| For loop | `for "_i" from 0 to 10 step 2 do {..}` | numeric loop |
| Switch | `switch (x) do { case 1: {..}; default {..} }` | equality |
| Wait for condition | `waitUntil {cond}` | suspends until true |
| Suspension | `sleep 1` | suspends N seconds |
| Thread | `spawn {..}`, `execVM "f.sqf"` | creates a cooperative thread |
| Scope | `private ["_a","_b"]`, `params [...]` | scope declaration |
| Comment | `// line` and `/* block */` | |
| Preprocessor | `#include`, `#define`, `#ifdef` | via `PreprocC` |

### 3.1 Command call

The command is the first token; the argument comes on the right. When the command expects several
values, they are packed into an array:

```sqf
_pos  = getPos player;              // command + argument
_dir  = getDir player;              // same
player setPos [x, y, z];            // three values in an array
_unit setDamage 0.5;                // one scalar
```

### 3.2 A code block is a value

`{ ... }` **executes** nothing: it creates a value of type `CODE`. To execute, use `call`,
`spawn`, `execVM` or pass the block to a command that accepts code (`waitUntil`, `then`).

```sqf
_meuBloco = { hint "rodou"; };
call _meuBloco;                     // runs now, in the same thread
_meuBloco spawn {};                 // schedules in a new thread
```

### 3.3 Scope

- `_x` is local. Without `private`, a local variable "leaks" into the calling script.
- `private ["_a", "_b"]` declares locals in the current scope.
- `params ["_a", ["_b", 0]]` declares and validates types/default values.
- A name without `_` is a mission global (`missionNamespace`).

```sqf
private _soma = 0;
{
    private _v = _x;                // _x is the current forEach element
    _soma = _soma + _v;
} forEach [1, 2, 3];
```

### 3.4 Control structures

```sqf
if (alive player) then {
    hint "vivo";
} else {
    hint "morto";
};

while { _i < 10 } do {
    _i = _i + 1;
    sleep 0.1;                      // hands control back to the engine
};

for "_i" from 0 to 10 step 2 do {
    diag_log str _i;
};

switch (_tipo) do {
    case "civil": { hint "civil"; };
    case "militar": { hint "militar"; };
    default { hint "outro"; };
};
```

### 3.5 Arrays

0-based index, dynamic size, heterogeneous:

```sqf
_arr = [1, "dois", [3, 4]];
_first = _arr select 0;             // 1
_arr set [3, "novo"];               // grows automatically
_n = count _arr;
{ diag_log str _x } forEach _arr;
```

### 3.6 Strings and numbers

```sqf
_texto = "linha com ""aspas"" internas";   // doubled quotes
_num   = 42;                                // int
_real  = 1.5;                               // float
_bool  = true;                              // boolean
```

## 4. How the engine executes SQF

The decisive point is that SQF is **not interpreted line by line by a naive parser**.
It is compiled to bytecode and run by a cooperative VM with a per-frame budget.

- `lib/scripts.cpp:53-74` — `Script` constructor: `_baseTime = Glob.time`,
  `_maxLinesAtOnce = 100`. **`_maxLinesAtOnce` is the lines-per-frame budget**:
  an SQF thread executes at most 100 lines and hands back control.
- `lib/scripts.cpp:76-93` — `ReadLine()` reads the file character by character, skips leading
  spaces and handles `\r\n`.
- `El/Evaluator/expressCompiler.cpp` (95 KB) compiles the tree.
- `El/Evaluator/expressInterpreter.cpp` (21 KB) interprets it.
- `El/Evaluator/scriptVM.cpp` bridges to the engine.

Practical consequence: a tight loop **without `sleep`** does not freeze the game — it consumes
the frame's 100 commands and comes back on the next frame. The symptom is **FPS drop**, not a
freeze. This is recorded in `1.md` §1.2.3.

## 5. Concurrency: `spawn`, `execVM`, `call`

| Form | Where it runs | When it returns | Use |
|---|---|---|---|
| `call block` | current thread | immediately, with the value | pure function |
| `_h = block spawn` | new thread | returns a `Script` handle | long task |
| `_h = execVM "f.sqf"` | new thread, reads file | returns handle | external script |
| `waitUntil {cond}` | current thread | when the condition becomes true | cooperative polling |
| `sleep n` | current thread | n seconds later | pause |

The 100-lines/frame budget in `lib/scripts.cpp:53-74` is what makes `spawn` cheap:
there is no OS thread, only an entry in the engine's script queue.

## 6. Preprocessor

SQF accepts preprocessor directives via `PreprocC`:

```sqf
#include "\minha_pasta\config.hpp"
#define MINHA_MACRO 10
#ifdef MINHA_MACRO
    diag_log "definida";
#endif
```

This is used heavily by DayZ to inject `CfgVehicles`, `CfgWeapons` and functions
shared between client and server.

## 7. Classic errors (and how the engine reacts)

| Error | What happens | Evidence/behavior |
|---|---|---|
| `while {true} do {}` without `sleep` | FPS drops, game continues | 100-lines/frame budget |
| `2^10` expecting power | not SQF; in Enforce `^` is XOR | see Enforce page |
| `_arr select 10` out of the array | returns `nil` and logs an error | no exception |
| local variable without `private` | can overwrite the caller's local | dynamic scope |
| missing `then` in `if` | script compilation error | `if (...) then {...}` |
| `sleep` inside `call` | suspends the entire calling thread | use `spawn` |

## 8. Relation to Enforce

The 0.45 engine has both VMs. SQF is the legacy one (missions, `init.sqf`), Enforce is the
modern one (`Enfusion/src/script/`). They share the `TimeManager` and the same frame
budget: **a slow script in either one steals drawing time** (see
`World::Simulate` in `lib/world.cpp:11795`, the `SimulateScripts` call at `12213`).
